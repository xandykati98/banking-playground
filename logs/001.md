## Cursor SDK - What Matters for This Project

The right pattern is **`Agent.create` + `agent.send`** (pattern 2), because:
- You need the agent to modify files (the virtual DOM JSONs) in the Flutter project's directory
- It runs **locally** with `local: { cwd: "<flutter_project_path>" }`
- The agent has full file system access to that `cwd`, so it can read, edit, and create files via diffs natively — no custom tooling needed
- You stream the response back to Flutter via SSE or WebSocket so the UI can show progress

The TypeScript server flow will be:
```
Flutter (HTTP POST /prompt "make it dark") 
  → Node server 
    → Agent.create({ local: { cwd: flutter_path } }).send(prompt + system instructions)
    → Agent edits layout JSON files in cwd
  → Server responds with done
Flutter file watcher detects change → rebuilds widget tree
```

## Architecture Design

### The "Virtual DOM" — JSON Layout Files

```
flutter_app/
  lib/
    layout/
      current/           ← agent reads + writes here
        dashboard.json
        profile_card.json
        stats_row.json
      defaults/          ← NEVER touched by agent (system instructions will forbid it)
        dashboard.json
        profile_card.json
        stats_row.json
```

Each file is a typed JSON component descriptor. Example:
```json
{
  "id": "profile_card",
  "type": "ProfileCard",
  "order": 1,
  "visible": true,
  "props": {
    "name": "Alex",
    "balance": "$12,430.00",
    "backgroundColor": "#1A1A2E",
    "accentColor": "#E94560"
  }
}
```

Flutter has a `LayoutLoader` service that watches `current/` for file changes and rebuilds the widget tree from the JSON. Reset = copy `defaults/` → `current/`.

### TypeScript Server

```
agent_server/
  src/
    server.ts        ← Express HTTP server, POST /prompt endpoint
    agent.ts         ← Cursor SDK agent factory + prompt handler
    instructions.ts  ← System prompt: "you are a UI editor, edit layout/current/ only"
  package.json
  tsconfig.json
  .env              ← CURSOR_API_KEY
```

The agent's system instructions will explicitly say: **"Do not read or modify `layout/defaults/`. Only modify files in `layout/current/`."** Since the Cursor agent respects its instructions and won't be shown those paths, the defaults are effectively protected.

## Flutter Project Startup

```bash
# 1. Create the Flutter project
flutter create --org com.challenge --project-name banking_playground banking_app
cd banking_app

# 2. Verify it runs
flutter run
```

Key dependencies to add to `pubspec.yaml`:
- `flutter_riverpod` — state management (drives reactive rebuild when JSON changes)
- `watcher` — file system watching for `layout/current/`
- `json_annotation` + `json_serializable` — typed JSON → Dart model
- `http` — calls the TypeScript agent server

Then the Node server alongside it:
```bash
# In a sibling folder
mkdir agent_server && cd agent_server
npm init -y
npm install @cursor/sdk express cors
npm install -D typescript @types/node @types/express ts-node-dev
```

And a root `package.json` (or `Makefile`) with:
```json
"scripts": {
  "dev": "concurrently \"cd banking_app && flutter run\" \"cd agent_server && npm run dev\""
}
```

4. **TypeScript server** — `POST /prompt` → Cursor SDK agent → edits files in `current/`
5. **Input bar in Flutter** — text field that POSTs to the server, shows loading state

7. **Polish** — banking UI design, animations on component changes
