The problem now is twofold: first, we need to find a way to reliably hot reload the app when the app shell changes, and we need to make the chat UI orders of magnitude better. We need to let the agent reset the state too.

## Solutions implemented

- **Hot reload**: Flutter is launched with `--vm-service-port=8181 --disable-service-auth-codes`. After every successful `/prompt`, the server connects to the VM Service WebSocket (`ws://localhost:8181/ws`), calls `getVM` to find the running isolate, then calls `reloadSources` — identical to pressing `r` in the Flutter terminal.

- **Agent reset via MCP tool**: Extracted all layout helpers into `src/layout.ts`. Created `src/mcp_server.ts`, a standalone MCP stdio server that exposes a single `reset_ui` tool. `Agent.create` now passes this server via `mcpServers`, so the agent can call `reset_ui` mid-run and get confirmation before replying. The `/reset` HTTP endpoint also fires a hot reload now.
