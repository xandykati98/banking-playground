The problem now is twofold: first, we need to find a way to reliably hot reload the app when the app shell changes, and we need to make the chat UI orders of magnitude better. We need to let the agent reset the state too.

## Solutions implemented

- **Agent reset via MCP tool**: Extracted all layout helpers into `src/layout.ts`. Created `src/mcp_server.ts`, a standalone MCP stdio server that exposes a single `reset_ui` tool. `Agent.create` now passes this server via `mcpServers`, so the agent can call `reset_ui` mid-run and get confirmation before replying. The `/reset` HTTP endpoint also fires a hot reload now.

## Hot restart (replaces VM service approach)

The `reloadSources` VM service approach only handled minor changes — structural Dart changes (new classes, imports, widgets) required a full hot restart (`R`), which `reloadSources` can't do.

- Replaced VM service WebSocket with `src/flutter_process.ts`: the server now spawns `flutter run -d chrome --machine` directly as a child process and owns its lifecycle.
- `--machine` mode outputs newline-delimited JSON; the process manager parses `app.start`/`app.started` events to capture the `appId`, then writes `app.restart` commands to Flutter's stdin (`fullRestart: true`) — identical to pressing `R`.
- `npm run dev` now only starts the agent server; Flutter is spawned by the server itself.
- `/reset` now awaits the restart (was fire-and-forget before) so Flutter always recompiles after files are restored.
- `/prompt` also awaits restart before responding, so `onPromptComplete` (layout reload) runs against already-recompiled code.
- Added a loading spinner in `main.dart` (`_loaded` flag on `_LayoutNotifier`) so the app shows a spinner instead of a blank white screen while the first layout fetch is in flight after a restart.
- Reset was only applying JSON colors (via the 3s poll) but not recompiling Dart: Flutter's incremental compiler was skipping recompilation when file content matched a cached artifact. Fixed by using `writeFileSync` instead of `copyFileSync` for all reset writes, which always updates mtime and forces Flutter's watcher to detect the change.
